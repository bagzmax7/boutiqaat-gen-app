# Boutiqaat Creative AI Studio — Clean Database Blueprint (Release 1)

This directory contains the **100% clean, production-ready database** structured according to the official **`User Profiles - Creative AI Studio`** specification.

All historical test data, old user accounts, and sample credentials have been completely wiped. The system is configured for **Microsoft Graph / Entra ID Single Sign-On (SSO)** with email-driven role registries and Row-Level Security (RLS) enforcement.

## 🛡️ Scope Breakdown: Permitted vs. Forbidden Actions

### 1. 👤 Creator Profile (`Scope: Own Only`)
*Editors across Content, Digital Marketing, and Marketing.*
* **✅ CAN PERFORM:**
  * Generate / dispatch new asset (Social Resize, Bg Remove, Retouch, Flow)
  * Regenerate / retry own previous tasks
  * Edit generation parameters on own tasks
  * Delete a generation from own history
  * Download own generated asset (**instant, no approval gate**)
  * View own generation history
  * View own individual usage stats
  * View own profile
* **❌ CANNOT PERFORM (Blocked at Gateway / RLS):**
  * 🚫 View or download assets from team members
  * 🚫 View team generation history or team roster
  * 🚫 Access team or cross-department KPI reports
  * 🚫 Access the Task Monitor / Console
  * 🚫 Add, edit, or remove user accounts
  * 🚫 View or modify department budgets and ceilings
  * 🚫 View the audit trail
  * 🚫 Manage external API keys (RunningHub, Supabase)

---

### 2. 👔 Manager Profile (`Scope: Own + Department Team`)
*Department / Team Leads (e.g. Content Lead, DM Lead).*
* **✅ CAN PERFORM:**
  * Generate / dispatch new asset (Own workspace)
  * Regenerate / retry own tasks AND team members' tasks
  * Edit generation parameters (Own drafts)
  * Delete generation from history (**Own tasks ONLY**)
  * Download own generated assets AND team assets (No approval gate)
  * View team generation history and team roster
  * View and export team KPI reports (productivity, quality, adoption, cost)
  * View team audit trail
* **❌ CANNOT PERFORM (Blocked at Gateway / RLS):**
  * 🚫 Delete tasks generated by team members (Own tasks only)
  * 🚫 View platform-wide / other departments' generation history
  * 🚫 Access cross-department KPIs or platform-wide cost analytics
  * 🚫 Access global Task Monitor / Console
  * 🚫 Export platform billing data
  * 🚫 Add or remove user accounts
  * 🚫 Assign user roles or assign managers to teams
  * 🚫 Adjust user or department budget ceilings
  * 🚫 Manage platform API keys (RunningHub, Supabase)

---

### 3. 🛡️ Admin Profile (`Scope: Platform-Wide / All`)
*Studio Platform Owner, IT/Ops, and AI Strategy leadership.*
* **✅ CAN PERFORM:**
  * Generate / dispatch new asset (Own workspace)
  * Regenerate / retry ANY task across all departments
  * Delete ANY generation from platform history
  * Download ANY generated asset across all departments
  * View full platform generation history and global Task Monitor Console
  * View cross-department KPIs and export billing/cost ledgers
  * Add / remove user accounts and assign roles / departments
  * Assign managers to teams
  * Set department and user monthly budget ceilings
  * View complete platform-wide audit trails
  * Manage external API keys (RunningHub, Supabase)
  * Configure Brand Kit & Catalog Connector (Roadmap items)
* **❌ DESIGN BOUNDARY:**
  * 🚫 Modify active draft parameters belonging to another user directly (dispatches under Own scope)

## 🌐 API Endpoint & Row-Level Security (RLS) Mapping

| API Route / Action | HTTP Method | Minimum Role | Evaluation Filter (SQL / RLS Logic) |
| :--- | :--- | :--- | :--- |
| `/api/tasks/generate` | `POST` | `CREATOR` | `user_id = auth.uid()` |
| `/api/tasks/{id}/retry` | `POST` | `CREATOR` | **Creator:** `user_id = auth.uid()`<br/>**Manager:** `department_id = auth.dept_id()`<br/>**Admin:** `TRUE` |
| `/api/tasks/{id}/delete` | `DELETE` | `CREATOR` | **Creator & Manager:** `user_id = auth.uid()` *(Manager cannot delete team tasks)*<br/>**Admin:** `TRUE` |
| `/api/tasks/{id}/download` | `GET` | `CREATOR` | **Creator:** `user_id = auth.uid()`<br/>**Manager:** `department_id = auth.dept_id()`<br/>**Admin:** `TRUE` |
| `/api/tasks/history` | `GET` | `CREATOR` | **Creator:** `user_id = auth.uid()`<br/>**Manager:** `department_id = auth.dept_id()`<br/>**Admin:** `TRUE` |
| `/api/analytics/team` | `GET` | `MANAGER` | **Manager:** `department_id = auth.dept_id()`<br/>**Admin:** `TRUE` |
| `/api/analytics/platform` | `GET` | `ADMIN` | **Admin:** `TRUE` *(Creator/Manager ➔ 403 Forbidden)* |
| `/api/users/manage` | `POST / PUT` | `ADMIN` | **Admin:** `TRUE` *(Creator/Manager ➔ 403 Forbidden)* |
| `/api/budgets/ceiling` | `PUT` | `ADMIN` | **Admin:** `TRUE` *(Creator/Manager ➔ 403 Forbidden)* |
| `/api/audit-logs` | `GET` | `MANAGER` | **Manager:** `department_id = auth.dept_id()`<br/>**Admin:** `TRUE` |

## 🚀 Microsoft Graph SSO Onboarding Guide

To grant an employee access to the studio:
1. Open the corresponding role registry file in `tables/`:
   - To add an **Admin**: Add email to `admins.json`
   - To add a **Manager**: Add email & `department_id` to `managers.json`
   - To add a **Creator**: Add email & `department_id` to `creators.json`
2. When the user logs in via **"Sign in with Microsoft 365"**:
   - Entra ID returns their verified corporate email and permanent `ms_graph_id`.
   - The system matches their email, assigns their role and department, and creates their entry in `users.json`.

## ☁️ Deploying to AWS (RDS PostgreSQL / Aurora)

To migrate this database to AWS RDS:
1. Provision an **AWS RDS PostgreSQL** or **Amazon Aurora Serverless v2** instance.
2. Run the SQL migration script:
   ```bash
   psql -h <RDS_ENDPOINT> -U <USER> -d <DB_NAME> -f schemas/000_release_1_architecture.sql
   ```
3. Update `.env.production` with your RDS connection string.
